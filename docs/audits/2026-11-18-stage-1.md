# Audit of 2026-11-18: Stage 1's end

The stage audit that closes Stage 1, as the owner's method describes it (`audits.md`). It follows
the [audit of 2026-11-17](2026-11-17-architecture-and-contribution.md), which covered architecture,
contribution, security, data contracts and recovery, and whose decisions are ADR-0043 to ADR-0046;
those dimensions are not repeated, only its open findings checked again.

## Scope

- **Dimensions**: correctness, edge cases, tests, performance and resources at rest, dependencies,
  accessibility, readability, documentation, and the whole debt; the open findings of 2026-11-17;
  the questions `docs/PLAN.md` put to this audit.
- **Code**: the repository at `4624243`; what the audit changed is in the commits from `3613082`
  to `7e87725`, and in the fork's `ba942f93b7`. The fork was otherwise read only where the debt
  cites it.
- **How**: one reviewer per group of dimensions, read only, each given the code and the bar and not
  the expected conclusions; a challenger on the strongest model attacked the draft
  recommendations. Every finding below was checked by the lead: a test that failed first, a
  command, or the exact line. Reviewers' figures taken on a loaded machine are marked so.
- **Not run**: no real provider turn; nothing on the owner's data. The machine's load was 10 to 55
  throughout (other sessions), so every timed figure is disturbed.

## Verdict

- **Stage 1's tools are sound; the frozen code was not.** The shared core and the egui client
  crashed on ordinary input from outside: a tool label in Chinese, an `&` before Japanese text, a
  link with `%` before an accent, an SVG's declared size, deep nesting, a server's chunk size. Six
  crashes were fixed here, each with the test that failed first; eight more defects of the client,
  two of them crashes, are M1.7's.
- **The most serious finding was live**: the fork, as the owner's `pluto-server`, had T3 Code's
  analytics on by default, sending each turn's provider, model, effort, result, duration and
  tokens to T3's PostHog, under an id hashed from Codex's or Claude Code's account file. A test
  proved the default sent; the fork's default is now off and it reads no other program's file,
  and the owner's NixOS change turns it off once switched to.
- **The documents hold the direction but not one reading of it.** 36 of 46 ADRs are linked by
  amendments, 13 contradictions had no winner, and the PLAN, the ROADMAP and AGENTS.md are over
  their word limits. The owner's decisions resolve the contradictions that block M2.0; the others
  are planned with the milestone that next decides their topic.
- **The bar is not met where the frozen clients stand**, and is not tuned there: accessibility,
  resources at rest and the budgets M1.2 found missed stay with the egui client until Stage 5.
- **Not checked**: the budgets on an idle machine (the load was 10 to 55 all night); the client's
  text functions under fuzzing; the lightbox's texture limit on a GPU (reasoned from the sources).

## Fixed during the audit

Each with the test that failed first; `scripts/check.sh`, `--apk` and CI green.

- **Crashes on input from outside** (the bar: bad input never crashes a client):
  - a tool label whose suffix cut fell inside a multibyte letter (Chinese, Russian) panicked in
    `compact_tool_label` (`crates/pluto-core/src/timeline.rs`), on the desktop and the phone;
  - a chunk size past the body, or past `usize`, panicked or overflowed in `dechunk`
    (`crates/pluto-core/src/http.rs`), from any host an image may come from;
  - the client kept its own copy of `percent_decode` (`src/ui/md_links.rs`), which sliced inside a
    letter after `%` (`notes/%aé.md`); it now uses the core's, which did not;
  - an SVG of 70 bytes declaring 100,000 px a side asked for 40 GB and aborted the client
    (`src/ui/attachments.rs`); it now meets a PNG's limits, 16,384 px a side and 512 MiB;
  - quotes, lists or `<details>` nested thousands deep overflowed the stack in the Markdown parser
    and renderer (`src/ui/markdown.rs`); past 32 levels they now join their parent.
- **Wrong results**: diff names holding a space kept git's trailing tab, and names outside ASCII
  stayed C-quoted (`crates/pluto-core/src/diff.rs`); the `Host` header dropped the port and an IPv6
  address's brackets (`http.rs`, RFC 9112 §3.2).
- **Resources**: the preview's browser, found but failing to start, left its temporary profile and
  two pipe descriptors (`src/preview.rs`, `launch()`); the profile is now a type that removes
  itself, the pipes `OwnedFd`.
- **Code rules**: ten `unsafe` blocks lacked the `// SAFETY:` comment AGENTS.md requires, five in
  `preview.rs` and five in `protocol.rs`; the fix removed two of `preview.rs`'s (`OwnedFd`) and
  justified the eight left.
- **Dependencies**: `cargo deny` failed on main from 2026-11-17 (RUSTSEC-2026-0543, chrono
  unmaintained); ignored by the owner's decision until M2.0 picks jiff or time.

- **Privacy, in the fork** (its branch `pluto`, backed up first as a bundle, commit
  `ba942f93b7`, on the owner's word): T3 Code's analytics were on by default and identified the
  owner from Codex's `auth.json` or Claude Code's `.claude.json`, read at every start even with
  telemetry off. The default is off, the id is the server's own anonymous one, and each of the two
  tests failed first (an unset setting sent a batch to a local server; Codex's account id was
  read). The owner's NixOS module sets `T3CODE_TELEMETRY_ENABLED=false` too, built and waiting for
  the owner's switch. The owner's own T3 Code (`t3code-server`) has the same default; the owner
  chose to leave it.
- **One more crash**, found by the client's review: `decode_entities` (`src/ui/md_html.rs`) sliced
  inside a letter on `&` before Japanese, Chinese or Russian text in an answer's HTML.
- **The license** (owner's decision): `LICENSE-MIT` names HoneySlatt beside T3's notice, which
  stays while code ported from T3 remains; `LICENSE-APACHE` holds the text the tool crates
  declare; `SECURITY.md` sends reports to GitHub's private reporting.
- **The toolchain** is named (1.99.1) rather than the overlay's latest, every manifest declares
  its `rust-version`, and the fork's replay ran again to stamp the change.

The same mistakes were searched for elsewhere: slicing text at an offset computed from its length,
and sizes read from the network. Every other site cuts after an ASCII character found just before,
which is safe.

## Findings

Ranked by severity within each dimension; a finding fixed above is not repeated.

### Correctness and edge cases

From the client's review (`.delegation/s1audit-client/report.md`, local), each planned in M1.7:

- **Crash, reasoned from the sources**: the client keeps egui-wgpu's default device limits, which
  ask for textures of 8,192 px at most; `decode` accepts 16,384; the lightbox uploads the full
  image once zoomed past half its size, about five presses of `+` for a 10,000-px image on a
  1080p screen; `Context::load_texture` checks the size only in debug builds, and wgpu's default
  error handler panics. Not run: no window on the owner's desktop.
- **Drafts lost**: switching threads while a queued message is edited stores the queued text as
  the first thread's draft and overwrites the second's (`src/ui/queue.rs`, `src/app.rs`
  `select_thread`); quitting or crashing during the edit saves the queued text as the draft
  (`src/ui/drafts.rs` reads only the composer). Reasoned; the scratch tests did not run (disk
  full).
- **Security**: a paste into a terminal is wrapped in bracketed-paste markers without removing a
  `\x1b[201~` it holds, so clipboard text from a web page can end the paste and run what follows
  (`src/ui/terminal_surface.rs`). A paste attached to a message is written to
  `/tmp/pluto-paste-<uuid>` with default permissions and never deleted, though the code calls the
  folder private.
- **Freezes**: the terminal's link detection rescans each run of path characters from every
  start: 0.010 s for 5,000 characters, 0.425 s for 40,000, every frame the pointer hovers
  (measured idle, on a copy of the functions). The first emoji and a paste of any size wait on the
  disk on the interface's thread.
- **Memory**: an image fetched by itself may hold 256 MiB, read whole then copied, while `decode`
  refuses anything over 40 MiB; the 10-second timeout is per read, not total.
- **Lower**: `version_label` slices a provider's version at byte 4 (`src/ui/providers.rs`); a
  thread's title goes unescaped to `notify-send`; a drafts, stash or settings file that fails to
  parse is replaced at the next save, with no copy kept.
- **Covered and sound**: only 13 `unwrap` or `expect` in the client's non-test code, each guarded;
  terminal links open only `http`, `https` and `mailto`; the client reads no path an agent names;
  remote images and icons load by themselves only through `try_get_public` and its rule, which
  checks every redirect.
- **Not done**: a fuzz module over about 70 text functions was written but never ran (the scratch
  build filled the disk); `citations`, `prompt_history`, `plan_card` and others were read, not
  fuzzed.

### Tests

- 599 Rust tests pass three runs in a row; none is ignored or flaky.
- `crates/pluto-measure/tests/runs.rs:156,176` returns silently without a systemd user manager:
  in CI the test checks nothing.
- The Android app has 2 Kotlin tests, and CI runs neither them nor the APK build (ADR-0012).
- Mutation testing (`cargo mutants`): `pluto-recording`'s format, 16 of 16 mutants caught. The full
  run of `pluto-recording` (1,300 mutants) was cut by a restart; before it, 14 mutants survived, in
  `mask.rs`'s `strip`, `strip_claude` and `strip_grok` (`|` to `^`, `|=` to `&=`) and
  `pluto-record.rs`'s `wait_for_agent`. The masking of secrets in recordings is where a missed
  mutant matters most.
- No test of accessibility exists.

### Performance and resources at rest

Taken at a load of 11 to 37 (median 23): disturbed, to take again on an idle machine.

- The client at rest, 60 s: 4 frames, 3.2 wake-ups a second (budget 0; the known debt says 3.2).
- Start, from `main`: window and GPU ready in 149 ms warm, 301 ms cold; the first useful frame in
  949 ms warm, 1,130 ms cold, against 123 and 184 ms recorded. The gap is most likely the load; it
  is not a finding until measured idle.
- The 5,000-message thread loaded in 45.6 s in the bench; the bench's own peak memory 199 MiB.
- The fork at rest: 9.6 to 33.8 wake-ups a second (debt: 4 to 30).

### Dependencies

- Found: 89 semver-compatible updates waiting (among them `rustls-webpki`, `tokio`, `wgpu`);
  `flake.lock` of 2026-10-27; Rust 1.99.1, unnamed (`rust-bin.stable.latest`). Done, in four
  commits each with every check, `--apk` and the fork's replay: the toolchain named, the flake
  updated (nixpkgs of 2026-11-15), Rust 1.100.0 with a three-day minimum publish age and Cargo's
  `unused_dependencies` denied (none found; a probe showed it fires), then `cargo update` (about
  84 crates moved, 11 gone, releases of the last three days held). Clippy 1.100 flagged one loop,
  rewritten. Major updates of the frozen client's crates are left out: they leave at Stage 5.
- The six advisories already ignored are still needed: the newest parents still require them.

### Accessibility

The egui client meets none of the bar's four needs:
- its text is painted (`painter.galley`), so a screen reader reads almost none of it;
- about 260 controls have no accessible name, the composer's Stop button and the sidebar's thread
  card among them;
- no focus ring is drawn; the context menus answer only Escape from the keyboard, so renaming,
  archiving and deleting a thread have no keyboard path;
- the primary button's white label has a contrast of 2.7:1, under 4.5:1;
- reduced motion is not followed.

The Android app is much closer: its switches and radio buttons do not announce their state, and
its toasts are not read by TalkBack. `docs/uwui-needs.md` asks neither for a name and a state on
every control, nor for the whole application by the keyboard, nor for contrasts checked.

### Readability

The egui client, frozen (`.delegation/s1audit-client/report.md`):
- 191 of its 2,450 functions run 100 lines or more and 9 run 500 or more; the longest,
  `provider_models` (`src/ui/providers.rs`), 704 lines. The largest files: `src/ui/settings.rs`
  (4,351 lines), `src/ui/markdown.rs` (4,320), `src/ui/chat.rs` (3,409).
- Against "one way to do a thing": four ISO-to-milliseconds helpers named `millis` that disagree
  (`queue.rs` parses RFC 3339 strictly, the others use `timeline::parse_time`), and three file-name
  sanitisers with different rules (`chat_export.rs`, `chat_projects.rs`, `html_render.rs`); the
  client also kept its own copy of the core's `percent_decode`, the one that crashed.
- Helpers used only by tests live in non-test code: `draft_model_in`, `expanded_turns`,
  `load_offline`, `load_offline_reply`, `renaming_thread`, `use_connection_for_tests`.

None of it is fixed in frozen code; the uwui client starts from the new foundation's rules.

## Decisions

The owner's, on 2026-11-18, each put with its options, costs and a recommendation, once a
challenger had attacked the draft (`.delegation/s1audit-challenge/report.md`, local).

- **chrono's advisory** ignored until M2.0 picks jiff or time.
- **Rust 1.100** (from a read-only analysis by another session, checked again here): the preview's
  leak fixed now on 1.99.1, without `DropGuard`; the toolchain pinned and moved to 1.100 in its own
  commit at this audit's end, with Cargo's `unused_dependencies` lint and a three-day
  `registry.global-min-publish-age`; the new APIs left to the new foundation, on a measured cost.
- **The fork's analytics** turned off in the fork and in the owner's NixOS module; the owner's own
  T3 Code left as it is.
- **The branches**: `m16b2b` pushed untouched, reviewed and merged with Stage 5's campaigns;
  `stage2-design` kept until M2.0's design session has read it, then archived off the machine.
- **The client's review**: `decode_entities` fixed now; the other eight in M1.7.
- **The abstraction rule**: stricter than the global one, an exception only where an accepted ADR
  names it (AGENTS.md).
- **The protocol's version**: M2.0's question; **Stage 3's channel**: two channels, steering and
  interrupts in.
- **The ADRs' chains**: planned topic by topic, as above.
- **The scenarios**: one list in the ROADMAP.
- **The fork's credential probes** (Claude's resets, Antigravity): kept until Stage 5, the
  accounts' risk recorded.
- **The non-durable writes**: the drafts' in M1.7, the others leave with the client.
- **Agents' pages and MCP apps**: a default-deny Content-Security-Policy in M1.7.
- **Android in CI**: a filtered CI job in M1.7.
- **The dependencies**: updated at this audit's end, in order: the toolchain named, the flake,
  Rust 1.100, then `cargo update` with the fork's stamp written again.
- **The vendors' paths and terms**: written in M1.7.
- **The license**: Pluto's notice added, T3's kept until no code of T3 remains (Stage 5).
- **The Android app**: frozen except fixes, like the egui client.
- **Accessibility**: asked of uwui only.
- **The debt without a milestone**: the light theme's dead paths deleted in M1.7; the rest given
  its milestone.
