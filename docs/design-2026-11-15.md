# Design session of 2026-11-15: Pluto becomes a harness

A temporary record. The owner answered a design interview on 2026-11-15 and took the decisions
below. The next session turns them into ADRs, a new `ROADMAP.md` and the PLAN of the new Stage 2,
shows them to the owner, then deletes this file. Until then, this file is the decisions' home.

The surveys behind it are local to the owner's machine, in `.delegation/design-*/report.md`, each
page they read saved beside them: the harnesses and their rankings, the providers' terms, the
all-in-one applications and design tools, the Rust building blocks, the personal agents, how a
harness stays able to change, the owner's own projects and agent tooling, and a challenge of the
recommendation.

## Why the direction changes

Until now Pluto was to relay other vendors' agents through a server of its own
([ADR-0004](adr/0004-plutos-own-server-in-rust.md)), with a small harness of its own for local
models after Stage 3 ([ADR-0011](adr/0011-plutos-own-harness-minimal-and-measured.md)). The owner
wants a real harness at Pluto's core, for four reasons: control over the brain (prompts, tools,
context, memory), no dependence on vendors' churn, less weight, and agents that behave alike.

Facts that shaped the decisions, from the surveys:
- Anthropic allows a subscription only in its unmodified `claude` binary, signed in by the user;
  a third-party harness needs an API key, far dearer for the owner's use. OpenAI allows ChatGPT
  plans in open-source local apps through its Responses API (a preview).
- Claude Code's mods (since 2026-10-01) let a plugin rewrite system-prompt sections, answer tool
  calls, and read usage, cost and plan limits, without modifying the binary. They cannot replace
  its loop or remove a past turn.
- At the top of Terminal-Bench 4.1 the model sets the ceiling; a harness moves small and local
  models most. No stable Rust harness library exists; the stable surfaces are protocols (MCP, ACP,
  Codex's app-server).
- The owner's own delegation method is already a harness made of scripts over six tools; its
  ledger shows the bookkeeping, the usage limits and re-read context as the main costs.

## What the owner wants

- Everything configurable; extensions; separable pieces; skills, hooks and agents as text.
- Design as a first-class space: interface mockups, design systems, graphics and logos, a canvas.
- Owner first, public later. Surfaces: the uwui desktop client, a complete TUI, a phone that does
  everything.
- The owner's delegation method native at the core.
- Judged on public benchmarks, context cost, speed and resources. Local models equal for all.
- Every mode of autonomy: followed closely, overnight milestones, triggered, always there.
- A context inspector at every turn.
- Spaces: deep research with replayable sources, browser and computer use, publishing a page.
  Capabilities: editing the real running app or mockup visually, tools that show their own UI,
  recording a know-how as a skill.
- A full personal assistant: a morning brief and monitoring; mail, calendar and lists; a second
  brain of notes as files; the machine and the NAS. Mail through IMAP, Tuta through TutaBridge, a
  separate program. Never delete without a way back; money and messages sent on the owner's behalf
  only with an explicit approval that shows the action, the target and every recipient. It runs on
  the desktop first, a NAS or a server later. Full voice conversation, local.
- Channels: Pluto's own apps. Signal and Matrix stay an open path, not planned.
- Still held: the market bar ([ADR-0017](adr/0017-pluto-measured-against-the-market.md)), the
  triage and the [specification](specification.md), the chat
  ([ADR-0020](adr/0020-the-chat.md)), Rust without Node, a server with clients and a relay, the
  history imported, Android in Kotlin first.

## Decisions

1. **One kernel, two products.** The work (code, chat, design, orchestration) first; the personal
   assistant later, as its own daemon with its own system user, vault, budget and rights. Both
   show in the same application.
2. **Three kinds of engine under one thread model**: Pluto's own loop; vendors' engines (Claude
   Code driven through a Pluto mod, Codex's app-server, Copilot's SDK); ACP for the other agents.
   The main work stays on Claude Code with the mod. Pluto's loop runs everything it may (local
   models, DeepSeek, API keys and credits, ChatGPT's plan), and is measured against the vendors'.
3. **Moved to the PLAN's Ideas**: the code editor
   ([ADR-0019](adr/0019-a-code-editor-in-pluto.md); the architecture must not rule one out),
   office editors (agents write documents as files, Pluto previews them), joining calls, and
   actions on a smart home. Computer use stays
   ([ADR-0018](adr/0018-the-markets-features-and-the-triage.md)). Tools' own UI and agents' pages
   stay in uwui's isolated web view, as the specification says.
4. **How the harness is judged**: on frontier models, the vendor's own harness matched within the
   error margin, for fewer tokens; on local and cheap models, a measured lead. Measured on Pluto's
   bench (saved briefs replayed with their hidden checks) and a subset of Terminal-Bench, within a
   fixed monthly budget for runs.
5. **The order**: (1) the bench and the session log's format; (2) `pluto-agent` and its TUI:
   Pluto's loop, its provider clients, the sandbox, a vault, the delegation object; the owner's
   delegated tasks move first; (3) Claude Code with the mod, Codex, ACP, quotas, exact costs;
   (4) the server, the protocol, pairing, the scheduler, the owner's inbox, Android on them, the
   history imported, the fork stopped; (5) the uwui client: chat, dashboard, design; (6) the
   assistant.
6. **The same repository, a new foundation.** New crates start from zero beside the frozen egui
   client. **Stage 1 closes now**, after its stage audit; the rivals' remaining campaigns move to
   the stage where a Pluto client exists to measure.
7. **Pluto's own provider clients** for Anthropic's Messages, OpenAI's Responses, Chat Completions
   and Ollama's native API, tested against the fake model service; a model registry from
   models.dev; a table of each provider's quirks.
8. **One `pluto-agent` process per agent session**, supervised by the server, its event log on
   disk; the same code is a library for the TUI and the phone.
9. **The method's mechanisms are native**: the delegation object (brief, base commit, hidden
   checks, proofs, report, ledger line), limits of depth, count and time, end conditions,
   provenance of content, exact costs, providers down and fallback. **The method itself stays in
   text files**: roles, the table of models, efforts, when to check.
10. **Rust without Node** holds for Pluto's code; Anthropic's `claude` and a small TypeScript mod
    remain while Claude Code is an engine. The assistant runs on API keys, DeepSeek or local
    models, never on a Claude subscription.
11. **The inspector appends by default**, keeping the prompt cache; rewriting the past shows its
    price first and asks.

Implementation choices of the lead, from the challenge: no WebAssembly extensions yet; `rmcp` for
outside tools, Pluto's own tools native; a sandbox after Codex's, with a vault, wrapping `claude`
and `codex` too; Pluto appends to Claude's system prompt by default and replaces it only per
thread, measured; a replay test fails if Claude Code's `-p` turns bare by default.
